1. Overall purpose

This project is a student CGPA prediction and academic guidance system. Its core purpose is to estimate a student’s projected CGPA from a set of academic, behavioral, and lifestyle factors and then suggest actionable study improvements.

The project does not just predict CGPA; it also tries to answer:
- What is the likely projected CGPA?
- Which factors are most associated with a stronger CGPA?
- What small changes in study habits could increase the CGPA?

This makes it a practical educational dashboard rather than a purely academic machine learning exercise.

2. What problem it solves

The app targets a common student need: understanding how habits such as study hours, attendance, assessment performance, sleep, extracurricular time, and accommodation relate to academic performance. It turns that into:
- a numerical prediction
- a recommendation engine
- a simple visual explanation of the drivers behind performance

In short, it is designed as a “CGPA forecast + study advice” tool.

3. Project structure and workflow

The app is a single Streamlit dashboard with four tabs:
- Predict & advise
- Data & EDA
- Model comparison
- Feature importance

The project flow is:

- Load the dataset:
  - the CSV contains fields like Department, Level, Current_CGPA, Last_SGPA, Carryovers, Study_Hours_Per_Week, Class_Attendance, Sleep_Hours_Per_Night, Accommodation, and Projected_CGPA
- Clean the data:
  - duplicate rows are removed
  - ordinal categories are mapped to numeric ranks
  - text CGPA values are converted to numbers and invalid values are removed
  - accommodation is converted to binary: off-campus = 1, on-campus = 0
- Build machine learning models
- Evaluate them with cross-validation and a holdout test set
- Select the best model
- Use it for prediction
- Recommend improvements by testing small step changes in actionable inputs

4. Data and preprocessing details

The app treats the dataset as a regression problem because the target variable is continuous:
- Projected_CGPA is the target
- It is in the range of 0 to 5, typical for CGPA systems

Important data engineering decisions in `CGPA.py`:

- Ordinal mapping:
  - values like “100L”, “200L”, “300L”, etc. become 0, 1, 2, 3, 4
  - categories like “Less than 5 hours” become ordered numeric levels
  - this preserves ranking while allowing machine learning models to interpret the variable sensibly

- Categorical handling:
  - Department is handled using OneHotEncoder
  - text categories are encoded without crashing on rare values

- Missing values:
  - numeric columns are imputed using median imputation
  - rows with missing target and current CGPA are dropped

- Data validity:
  - CGPA values are forced to numeric
  - impossible values below 0 or above 5 are set to NaN and removed

This is a solid preprocessing pipeline for a small student dataset.

5. Technical architecture

The project uses:
- Python
- pandas for data manipulation
- NumPy for array operations
- matplotlib for charts
- Streamlit for the web interface
- scikit-learn for machine learning pipelines

The important technical patterns are:

- Pipeline
  - used to combine preprocessing and model training into a single workflow
- ColumnTransformer
  - separates numeric and categorical columns
- SimpleImputer
  - fills missing numeric values with median
- OneHotEncoder
  - converts category columns like Department
- StandardScaler
  - standardizes numeric features where required
- KFold + cross_validate
  - evaluates models robustly
- train_test_split
  - creates a holdout test set

The app also caches expensive operations:
- @st.cache_data for dataset loading
- @st.cache_resource for model training

This reduces repeated computation when the dashboard reloads.

6. Algorithms used

The project compares two models:

- Linear Regression
  - the main model
  - used with standardized numeric features
  - strong baseline for interpretable coefficients

- Random Forest Regressor
  - ensemble of trees
  - 300 trees
  - minimum leaf size of 3
  - random_state fixed at 42

Why these models?
- Linear Regression is easy to interpret and often works very well when relationships are mostly linear and additive
- Random Forest captures nonlinear relationships and interactions

The training setup:
- train_test_split with test_size=0.2 and random_state=42
- KFold with 5 splits and shuffle=True, random_state=42
- cross_validate scoring:
  - neg_mean_absolute_error
  - neg_root_mean_squared_error
  - r2

The app chooses the “best model” based on the smallest cross-validated RMSE, not the test RMSE. After that, it refits that model on the full dataset for final use.

7. Prediction and recommendation logic

There is a real “decision support” component beyond just regression.

The app builds a recommendation engine:
- It identifies actionable features such as:
  - Study_Hours_Per_Week
  - Class_Attendance
  - Continuous_Assessment_Score
  - Past_Questions_Practice
  - Study_Groups_Participation
  - Work_Hustle
  - Extracurricular_Hours_Per_Week
- For each feature, it simulates one step improvement or reduction
- It asks: if the student changes this one factor by one level, how much would the predicted CGPA increase?
- It ranks the result by predicted gain and presents the best 3 recommendations

This is a model-based counterfactual estimator: “what would happen if this student moved one step in a positive direction?”

Important note from the code:
- this is not proof of causation
- it is pattern-based association learned from historical student-like data

That is a good scientific caveat and an honest limitation.

  - Test RMSE: 0.185

- Random Forest
  - CV MAE: 0.166
  - CV RMSE: 0.210
  - CV R²: 0.913
  - Test MAE: 0.168
  - Test RMSE: 0.205
  - Test R²: 0.932

Interpretation:
- The Linear Regression model performs better on this dataset than Random Forest
- Best model selected: Linear Regression
- It achieves a test RMSE of about 0.185 on a CGPA scale from 0 to 5
- This means the average forecasting error is around 0.18 CGPA points
- The model explains about 94.5% of variance on the test set based on R²

This is strong for a small, synthetic educational dataset.

11. Limitations and risks

This project is strong, but it also has important boundaries:

- Dataset is synthetic, not real student records
- The model is trained on a generated practice dataset rather than actual university data
- Predictions are not guaranteed to reflect real-world academic outcomes
- Recommendations are association-based, not proven causal effects
- It does not include temporal or longitudinal student progression
- No hyperparameter tuning beyond a basic random forest setup
- No deployment, backend, database, or authentication layer

In other words, it is a solid prototype and educational tool, not a production academic analytics system.
